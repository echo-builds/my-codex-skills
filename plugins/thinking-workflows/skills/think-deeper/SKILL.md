# 从信号到判断

不要把信息摘要冒充洞察。帮助用户从同一批材料中发现值得追问的变化、差异、矛盾和断点，再形成有证据边界的判断。

## 核心流程

### 1. 明确判断任务

先写清材料最终要帮助谁理解或决定什么。保持研究问题中性，不要把尚未发现的结论预埋进问题。

区分四层：

- 任务问题：本次要了解或决定什么；
- 观察事实：材料直接显示了什么；
- 解释假设：为什么会出现这些事实；
- 业务判断：这些事实对当前行动意味着什么。

### 2. 给信号分类

只保留可能改变判断的信息，并标记为：已验证事实、用户信号、解释性推断、决策主张、未知。

优先寻找六类高价值信号：

- 变化：同一对象前后为什么改变；
- 差异：相同目标下为什么采用不同做法；
- 矛盾：宣称、客观效果与主观反馈为什么不一致；
- 角色错位：使用者、购买者、受益者、推动者是否价值不同；
- 断点：需求、能力、流程、采用、实施或商业化在哪一环失效；
- 反常：什么事实不符合当前认知或主流叙事。

不要平均分析所有信息。选择最可能改变决策的 1-3 个信号深入。

### 3. 建立追问链

针对每个关键信号依次追问：

1. 发生了什么？证据是否可靠？
2. 为什么发生？至少列出两个竞争性解释。
3. 每个解释需要什么支持证据和证伪证据？
4. 问题具体发生在哪一层，而不是笼统说“体验不好”或“需求不足”？
5. 哪个解释成立会改变当前选择、优先级或下一步？

当材料涉及负面反馈时，分别检查：需求强度、核心能力、准确率或质量、操作流程、工作流适配、组织实施、价格与商业模式、地区或人群适用性。只有定位断点后，才能讨论机会。

### 4. 用反例约束判断

主动寻找反常案例和替代解释。询问：

- 什么事实会推翻当前判断？
- 看到的是共同趋势，还是样本选择造成的巧合？
- 对方没有做，是能力不足、时机未到，还是不值得做？
- 产品供给是否真的证明了用户需求？
- 个别用户喜欢是否能推出组织愿意采用或付费？

证据不足时输出“当前最合理的假设”和最低成本验证，不强行给确定结论。

### 5. 形成判断阶梯

每个核心判断按以下结构表达：

1. **结论**：当前最重要的判断；
2. **依据**：2-4 条能直接支持它的证据；
3. **机制**：这些证据为何能推出结论；
4. **边界**：尚不能推出什么，最脆弱假设是什么；
5. **影响**：它会改变哪个决策或下一步验证。

禁止从“某产品做了某功能”直接跳到“我们也应该做”。补齐用户问题、成立机制、真实效果、适用条件和自身能力。

### 6. 提炼核心叙事

在制作正式文档前，先用五句话讲清：

1. 原有认知或当前问题是什么；
2. 哪个关键信号使它受到挑战；
3. 最合理的解释是什么；
4. 因此形成什么判断；
5. 对行动意味着什么，仍需验证什么。

如果一分钟内讲不清主张、依据和未知，不要进入完整文档或正式可视化。不要把每个追问都扩展成一个并列方向；优先收束一个核心判断，其余降级为假设、附录或后续研究。

## 输出格式

根据任务复杂度输出以下最小集合：

- 关键事实与证据状态；
- 最值得深挖的 1-3 个信号；
- 竞争性解释及证伪条件；
- 当前核心判断、边界与业务影响；
- 一条可用于文档或汇报的核心叙事；
- 下一步最低成本验证。

需要参考具体案例时，读取 [references/examples.md](references/examples.md)。案例用于学习推理模式，不得把案例中的行业结论套用到新任务。
