## 1. Intake

Establish these variables before structuring:

| Variable | Question |
|---|---|
| Audience | Who will read or hear this, and what do they already know? |
| Decision | What should they decide, approve, understand, or do? |
| Core question | What single question must this communication answer? |
| Answer | What is the current best answer in one sentence? |
| Evidence | Which facts directly support it? |
| Constraints | What scope, deadline, format, sensitivity, or uncertainty matters? |

If information is missing, proceed with labeled assumptions when safe. Ask only when different answers would materially change the structure.

## 2. Pyramid tests

### Vertical test

For every parent-child relationship:

- Ask “why?”, “how?”, or “what does that mean?” of the parent.
- Confirm the children answer that question.
- Read children together and write the insight they imply.
- Confirm that insight is equivalent to the parent, not merely related to it.

### Horizontal test

For every sibling group:

- Use the same grammatical level.
- Use one organizing principle.
- Check overlap.
- Define the universe before claiming completeness.
- Prefer 2-5 main points unless the material genuinely requires more.

### Evidence test

Tag each statement mentally as:

- fact;
- interpretation;
- recommendation;
- assumption;
- unknown.

Do not use an interpretation as if it were a fact. Connect recommendations to explicit reasons and evidence.

## 3. Openings

### Decision or proposal

- Situation: stable context the audience accepts.
- Complication: change, tension, risk, or opportunity that makes action necessary.
- Question: the natural decision question created by the complication.
- Answer: the proposed conclusion or action.

Write these as a short narrative, not compulsory labels.

### Routine status update

1. Overall judgment.
2. Material progress or evidence.
3. Deviation or risk.
4. Next action and owner.
5. Decision or help needed.

### Executive verbal update

Use a 30-second core:

1. “结论是……”
2. “主要依据有……”
3. “当前最大风险是……”
4. “需要您决定/支持的是……”

## 4. Logical ordering

### Time or causal sequence

Use for processes, implementation, causes, or stages. Summarize actions by the result they jointly produce, not by “three steps.”

### Structural decomposition

Use when dividing a whole by geography, customer journey, organizational unit, system component, or another stable structure. Define the whole and use one partitioning dimension per level.

### Degree or priority

Use for problems, reasons, options, or recommendations ranked by impact, urgency, certainty, or feasibility. Name the ranking criterion.

### Deduction

Use when the reasoning genuinely follows:

1. a generally accepted rule or situation;
2. a statement about the case;
3. the resulting implication.

For executive communication, usually put the implication first and move the full deduction into supporting detail.

## 5. Message sentences

Replace topic headings with claims.

| Weak label | Strong message sentence |
|---|---|
| 项目进展 | 核心功能已完成，但数据迁移将使上线推迟一周 |
| 三个问题 | 当前交付风险主要来自需求冻结晚、接口不稳定和验收资源不足 |
| 用户反馈 | 新流程缩短了操作时间，但首次使用成功率仍低于目标 |
| 下一步计划 | 未来两周将优先消除上线阻塞项，而非继续扩展功能范围 |

For action groups, summarize the outcome. For descriptive groups, summarize the meaning of their commonality.

## 6. Common deliverables

### Proposal or approval request

1. Recommendation.
2. Why now.
3. Expected value and evidence.
4. Options and tradeoffs.
5. Risks and mitigations.
6. Required decision and next step.

### Weekly or project report

1. Overall status and judgment.
2. Outcomes achieved, not activity inventory.
3. Deviations and implications.
4. Next priorities.
5. Help or decision required.

### Review or retrospective

1. Overall result against goal.
2. What drove the result.
3. What should be repeated or changed.
4. Specific actions, owners, and checkpoints.

### Slide storyline

1. Write one complete message sentence per slide.
2. Read only the slide titles in sequence; they should form a coherent argument.
3. Use the body to prove the title.
4. Use charts to answer a defined question; put the answer in the chart title.
5. Keep one principal message per slide.

## 7. Review rubric

Score each dimension from 0 to 2:

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Audience fit | Audience need unclear | Partly addressed | Built around audience decision |
| Top-line answer | Missing | Present but vague | Specific and decision-ready |
| Vertical logic | Sections merely related | Some support gaps | Every level answers the level above |
| Horizontal logic | Mixed or overlapping | Mostly consistent | Comparable, ordered, and scoped |
| Evidence | Claims unsupported | Partial support | Facts, inference, and assumptions separated |
| Actionability | No next step | General next step | Decision, owner, timing, and risk visible |
| Concision | Detail overwhelms | Some redundancy | Detail is proportional to decision value |

Prioritize fixing any zero in top-line answer, vertical logic, evidence, or actionability.

## 8. Compact examples

### From activity list to management update

Input:

- interviewed users;
- discussed API design;
- fixed several bugs;
- launch may slip.

Structured result:

- Conclusion: Launch is likely to slip one week because API stability remains below the release threshold.
- Evidence: User validation is complete; core bugs are reduced; two high-risk API failures remain.
- Action: Freeze nonessential scope and resolve the two failures by Friday.
- Decision needed: Confirm whether to protect the original date by reducing scope or accept the one-week delay.

### From vague recommendation to supported recommendation

Weak: “We should improve the reporting process.”

Stronger:

- Recommendation: Standardize data definitions before automating report generation.
- Why: Most delays arise from repeated reconciliation, not from document production.
- Evidence needed: Reconciliation hours, definition conflicts, and error rates.
- Next step: Assign metric owners and approve one canonical definition per KPI.
