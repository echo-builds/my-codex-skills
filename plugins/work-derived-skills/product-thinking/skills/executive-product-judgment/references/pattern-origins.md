# 思维模式来源与解释

本参考用于维护和扩展 Skill，不要求每次调用都读取。它记录了从多场产品周会和产品方案内审中提炼出的稳定判断模式，避免后续迭代把 Skill 简化成通用检查清单。

## 稳定模式

### 结果而非产出

负责人不会把功能上线、模型变快或某项体验指标改善直接视为成功，而是继续检查使用深度、留存、增长质量和成本是否变化。

### 矛盾比顺畅叙事更有信息量

典型追问包括：好评改善为什么留存没有变化；解题指标改善为什么整体活跃下降；短期留存不错为什么长期留存快速衰减。

### 数据用于推翻解释

持续检查指标分母、样本量、显著性、用户结构、国家和渠道差异，并主动提出替代解释。重点不是证明项目有效，而是避免基于错误因果继续投入。

### 产品价值必须被外化

隐藏在深层页面、第二天才被动出现或没有用户预期的能力，很难产生价值。首次关键行为后应尽快让用户体验并理解长期价值。

### 以用户任务串联能力

拍题、问答、错题、课程、复习、学情和记忆不应作为孤立模块存在。它们应共同服务于一个长期任务，例如理解学生、发现薄弱点并持续安排学习。

### 需求存在不等于应该承接

某类 query 或使用行为规模很大，仍需判断它是否符合长期定位、是否强化产品心智，以及是否具备可持续成本和独特优势。

### 先验证脆弱假设

在投入复杂界面和完整系统前，先验证用户是否点击、是否理解、是否愿意回来，以及核心行为是否真的变化。

### 主动停止与重排优先级

历史投入、局部正向和团队已有计划都不是继续投入的充分理由。必须比较价值上限和机会成本。

## 不应复制的表象

- 强势、打断和否定式表达不是本 Skill 的目标；
- 会议现场给出的具体入口或 UI 方案只是启发，不是通用答案；
- 高层直觉也可能过早收敛，必须用证据边界和反事实检查约束；
- 宏观判断必须能落到用户行为、指标和最短实验，不能停在抽象叙事。
